# Control 2.11: Copilot Pages Security and Sharing Controls

**Control ID:** 2.11
**Pillar:** Security & Protection
**Regulatory Reference:** GLBA §501(b), FINRA 4511
**Last Verified:** 2026-08-02
**Governance Levels:** Baseline / Recommended / Regulated

---

## Objective

Establish governance controls for Copilot Pages and Copilot Notebooks as AI-generated collaboration surfaces in Microsoft 365. This control covers Cloud Policy decisions, storage in SharePoint Embedded, sharing restrictions, sensitivity labeling, retention, eDiscovery, and offboarding procedures so that Pages-related content is governed consistently with broader financial services data protection and records management expectations.

---

## Why This Matters for FSI

- **GLBA §501(b)** requires safeguards for customer information. Copilot Pages can aggregate content from multiple regulated sources into a new shareable artifact, which increases the need for clear creation, sharing, and retention controls.
- **FINRA Rule 4511** requires firms to preserve books and records that may include Copilot-generated summaries, working notes, or collaboration artifacts if they relate to firm business.
- **SEC 17a-3/4** may apply when Pages document advisory activity, investment research, client service workflows, or draft communications that become part of the business record.
- **Sarbanes-Oxley §§302/404** internal control expectations extend to new collaboration surfaces that can contain financial reporting support material or control evidence.
- **Information Barriers limitations** matter in broker-dealer and banking environments because Copilot Pages and Copilot Notebooks use SharePoint Embedded storage, where Information Barriers are not currently supported.

---

## Control Description

Copilot Pages (`.page` files) and Copilot Notebooks are stored in a single user-owned SharePoint Embedded container that is also used by Loop My workspace. In the SharePoint admin center, PowerShell, and Purview audit data, this container always appears with an application name of **Loop** — there is no separate Copilot Pages or Copilot Notebooks application filter. They are **not** stored in the user's OneDrive in the traditional sense, even though the container follows a lifecycle similar to OneDrive cleanup after user departure.

Creation and use are governed through Microsoft 365 **Cloud Policy**, while retention, eDiscovery, sensitivity labels, and DLP rely on SharePoint and Purview controls that apply to SharePoint Embedded content.

### Pages Security Controls

| Control Area | Description | Configuration Location |
|-------------|-------------|----------------------|
| **Creation and use** | Allow or block creation of Copilot Pages and Copilot Notebooks | Microsoft 365 Cloud Policy (`config.office.com`) |
| **Code previews** | Allow or block code previews in Copilot Chat and Pages | Microsoft 365 Cloud Policy |
| **Storage administration** | View and manage user-owned SharePoint Embedded containers | SharePoint admin center / SharePoint PowerShell |
| **Sharing scope** | Govern sharing of individual Pages, including external sharing when organization-level settings allow it | SharePoint sharing controls, Loop component settings, supported app sharing behavior |
| **Sensitivity labels** | Manually apply labels to Pages content and configure supported mandatory or default label policy settings | Microsoft Purview > Information Protection |
| **DLP** | Detect sensitive content and show policy tips for Pages content | Microsoft Purview > Data loss prevention |
| **Retention** | Apply lifecycle controls to SharePoint Embedded content | Microsoft Purview > Data Lifecycle Management > All SharePoint Sites |
| **eDiscovery / legal hold** | Search, review, export, and preserve content | Microsoft Purview eDiscovery; integrated custodian picker where available, with manual container targeting as fallback |
| **Information barriers** | Document unsupported scenarios and compensating controls | Governance decision; disable Pages/Notebooks where IB is required |

### Storage and Lifecycle Considerations

!!! warning "Information Barriers Are NOT Supported for SharePoint Embedded Content"
    **Information Barriers (IB) are not supported** for SharePoint Embedded content, which includes Copilot Pages and Copilot Notebooks. This is critical for FSI organizations with Chinese wall requirements — broker-dealers and firms that rely on Information Barriers to enforce MNPI segmentation between business units cannot depend on IB controls to prevent cross-barrier access to Copilot Pages or Notebooks. Organizations requiring Information Barrier enforcement **must disable Copilot Pages and Notebooks** for affected user populations or implement compensating controls (such as scoping Cloud Policy to exclude IB-affected groups). Organizations should verify this limitation against their current deployment before enabling Pages or Notebooks for any user group subject to information barrier policies.

### Sensitivity Labeling Limitations for Copilot Notebooks

Sensitivity labeling is supported for Copilot Pages but **not for Copilot Notebooks**. For Pages, users can manually apply published labels; mandatory labeling, default document labels, and label inheritance are supported. Automatic and recommended sensitivity labeling aren't supported for Loop components or Pages. Copilot Notebooks don't have container sensitivity labels because they share a user-owned container with Copilot Pages and Loop My workspace. Organizations should test supported label behavior on Pages and document that sensitivity labels aren't available as a Notebook-level control.

### Lifecycle Management Updates (2026)

**Departed user lifecycle (current):** Copilot Pages and Copilot Notebooks remain in the departing user's single user-owned SharePoint Embedded container. The container follows the OneDrive deletion lifecycle: it remains active for the tenant's configurable deleted-user retention period (30 days by default), then remains recoverable by an administrator during the 93-day recycle-bin period before permanent deletion. Administrators can use the "Grant access to containers" workflow to add a custodian who can copy content, or use SharePoint PowerShell `Set-SPOContainer -Identity <container> -CurrentPrincipalOwner <upn> -NewPrincipalOwner <upn>` to permanently reassign a user-owned container. Access and notification aren't automatic. Organizations should preserve, export, place on hold, or reassign the container before cleanup windows expire.

**Container recovery during soft delete:** Administrators can recover the entire SharePoint Embedded container during the soft-delete period using SharePoint admin center or PowerShell. Recovery is container-level; offboarding playbooks should identify which departed users had Pages/Notebooks content and document the escalation path for recovery requests.

**Recycle bin limitations:** Microsoft Learn states there is no end-user recycle bin for Copilot Notebooks, and neither administrators nor end users can recover individually deleted Copilot Notebooks. Organizations should train users to treat Notebook deletion as non-recoverable unless the broader container lifecycle recovery path applies, and should verify current behavior for Copilot Pages in their tenant.

!!! info "No Individual Notebook Recycle Bin (Current State)"
    As of the current Microsoft Learn guidance, individually deleted Copilot Notebooks cannot be restored by end users or administrators. Use retention, eDiscovery preservation, and container-level recovery planning for business records that may be stored in Pages/Notebooks.

**Group-owned Loop workspaces:** Group-owned containers are a supported ownership type for shared Loop workspaces associated with Microsoft 365 Groups, such as Teams channel workspaces. This doesn't change the storage model for Copilot Pages, Copilot Notebooks, and Loop My workspace, which remain together in a user-owned container.

| Scenario | Current Behavior | Governance Implication |
|---------|------------------|------------------------|
| **User creates first Page or Notebook** | A SharePoint Embedded container can be created for that user if policy allows | Creation policy should be intentional and scoped to approved users |
| **Loop disabled but Pages enabled** | Pages can still create the shared user-owned container | Review Loop and Pages policies together — the shared container is created when either the Copilot Pages/Notebooks policy or the Loop "Create Loop workspaces in Loop" policy allows creation for the user |
| **Pages disabled but Loop enabled** | The shared container can still exist because Loop can create it | Do not assume blocking Pages removes the container — to prevent the container entirely, disable both Loop and Pages policies for the same user |
| **User departure** | Container follows the configurable OneDrive cleanup schedule; administrators can add a custodian or permanently transfer the principal owner with SharePoint PowerShell | Preservation, export, hold, or reassignment should happen before cleanup windows expire |
| **Legal hold** | Supported; selection of the container in the eDiscovery custodian data source picker is rolling out, with manual container targeting required until available | Litigation response playbooks should cover both the integrated picker and manual fallback |
| **Information barriers required** | Not supported for SharePoint Embedded content | Disable or tightly scope Pages/Notebooks for IB-sensitive populations |

### Pages Sharing Guidance

| Sharing Pattern | FSI Guidance | Notes |
|----------------|-------------|-------|
| **Creator-only / specific people** | Preferred | Best fit for early rollout and regulated teams |
| **Broad internal sharing** | Review before enabling | Validate audience, purpose, and downstream recordkeeping obligations |
| **Interactive sharing through Loop-enabled apps** | Review carefully | Sharing behavior depends on Loop components being enabled in the Microsoft 365 ecosystem |
| **Guest / external sharing** | Avoid for regulated content | Product capabilities continue to evolve; validate exact behavior in your tenant before permitting any external scenario |

## Copilot Surface Coverage

| Microsoft 365 Application | Documented Behavior | Governance Notes |
|-------------------|---------------------|------------------|
| Microsoft 365 Copilot app and Copilot Chat | Create, view, and edit Copilot Pages | Primary creation and access surfaces |
| Teams, Outlook, Whiteboard, and OneNote | Share Pages as interactive components when Loop components are enabled | Without Loop components enabled, sharing behavior is limited to supported links and chat experiences |
| Loop app | View and edit Pages; apply supported sensitivity and retention labels | Shares the same user-owned SharePoint Embedded container |
| Copilot Notebooks | Organize Copilot Pages and references in a Notebook | Uses the same user-owned container; Notebook-level sensitivity labels aren't supported |

## Governance Levels

| Level | Requirement | Rationale |
|-------|-------------|-----------|
| **Baseline** | Scope Cloud Policy for who can create Copilot Pages and Copilot Notebooks and use their integrations; document SharePoint Embedded storage behavior; restrict sharing to named internal users where possible; cover Pages with SharePoint retention and DLP policies; document legal hold procedures, including manual container targeting where required | Minimum viable governance for introducing Pages without treating them as unmanaged scratch space |
| **Recommended** | All Baseline requirements plus: create separate policy scopes for approved business groups; decide whether code previews are allowed; test sensitivity labels, DLP, and eDiscovery on Pages content; add quarterly review of Pages sharing and usage; document offboarding preservation workflow | Balanced production governance for most FSI deployments |
| **Regulated** | All Recommended requirements plus: disable Pages/Notebooks for populations that require Information Barriers; require compliance review before enabling broad sharing; include Pages/Notebooks in records management procedures and examination evidence packs; perform annual control validation against SharePoint Embedded limitations | Stronger posture for environments with heightened supervision, records, or segmentation requirements |

## Setup & Configuration

### Step 1: Configure Creation and Use Policy

**Portal:** Microsoft 365 Cloud Policy service  
**Path:** `https://config.office.com` > **Customization** > **Policy Management**

1. Create or edit a policy that scopes approved users or groups.
2. Configure **Create and view Copilot Pages and Copilot Notebooks**.
3. For Baseline and Recommended tiers, scope the policy to approved security or dynamic groups instead of enabling it broadly by default.
4. Document the policy owner, target groups, and business justification.

### Step 2: Configure Code Preview Policy

**Portal:** Microsoft 365 Cloud Policy service  
**Path:** `https://config.office.com` > **Customization** > **Policy Management**

1. Review **Enable code previews for AI-generated content in Microsoft 365 Copilot Chat and Copilot Pages**.
2. Disable it unless there is a documented need for code-preview workflows.
3. If enabled, include code preview usage in secure development and data handling guidance.

### Step 3: Review Storage and Container Visibility

**Portal:** SharePoint admin center / SharePoint PowerShell

1. Confirm administrators can locate user-owned SharePoint Embedded containers for Pages/Notebooks.
2. Document how orphaned or ownerless containers are identified and escalated.
3. Record cleanup timing for departing users so evidence preservation occurs before container deletion.

### Step 4: Apply Sensitivity Labels and DLP

**Portal:** Microsoft Purview

1. Publish sensitivity labels appropriate for Pages content.
2. Test whether Pages that contain regulated material trigger the expected DLP policy tips and actions.
3. Document whether manual, mandatory, or default labeling is required for your environment; don't rely on unsupported automatic or recommended sensitivity labeling.

### Step 5: Configure Retention

**Portal:** Microsoft Purview > Data lifecycle management > Retention policies

1. Include **All SharePoint Sites** in the relevant retention policy scope so SharePoint Embedded content is covered.
2. Verify Pages and Notebooks are included in records management decisions for regulated business content.
3. Document any exceptions for ephemeral collaboration content and validate those exceptions with records management counsel.

### Step 6: Configure eDiscovery and Legal Hold Procedures

**Portal:** Microsoft Purview > eDiscovery

1. Test search and export of `.page` content.
2. Verify whether the user-owned container is available in the custodian data source picker; document the manual container URL workflow as the fallback while picker support rolls out.
3. Validate that your eDiscovery team knows how to find SharePoint Embedded-backed Pages content during examinations or litigation.

### Step 7: Document Unsupported and High-Risk Scenarios

1. Identify populations that depend on Information Barriers or other unsupported controls.
2. Disable or tightly scope Pages/Notebooks for those users.
3. Add Pages/Notebooks to offboarding, investigation, and incident response procedures.

## Financial Sector Considerations

- **Record-keeping classification:** Organizations should determine which Copilot Pages constitute books and records under FINRA Rule 4511 or SEC Rule 17a-4 based on business use, not file type alone.
- **Information Barriers limitation:** Because SharePoint Embedded content doesn't currently support Information Barriers, broker-dealers and firms with strict MNPI segmentation should treat Pages enablement as an explicit governance decision, not a default feature rollout.
- **Departing employee workflow:** Administrators can manually add a custodian or permanently reassign the user-owned container with SharePoint PowerShell. Offboarding procedures should include access notification and retention, export, hold, copying, or reassignment steps before the SharePoint Embedded container reaches cleanup deadlines.
- **Legal hold workflow:** Legal hold supports Pages content. The team should verify whether the integrated custodian data source picker is available and retain the manual container-targeting fallback in litigation procedures while the picker rolls out.
- **Training:** Users should understand that Copilot Pages are governed business content. They are not outside the firm's retention, discovery, or supervisory scope simply because they originate from a Copilot interaction.

---

## Verification Criteria

1. **Creation policy scoped:** Verify the Cloud Policy for **Create and view Copilot Pages and Copilot Notebooks** is applied to the intended users or groups only, recognizing that disabling it doesn't delete existing items and users with permission can still view and edit existing content.
2. **Code preview decision documented:** Confirm the code preview policy is either disabled or enabled with documented business justification.
3. **Storage visibility confirmed:** Verify administrators can identify user-owned SharePoint Embedded containers for Pages/Notebooks.
4. **Sharing posture validated:** Create a test Page and confirm sharing behavior matches the firm's approved model.
5. **Sensitivity and DLP controls tested:** Confirm Pages content can be labeled and that DLP policies detect test sensitive data.
6. **Retention coverage verified:** Confirm relevant retention policies covering **All SharePoint Sites** apply to Pages/Notebooks content.
7. **eDiscovery search tested:** Run an eDiscovery test for Pages content and verify results can be reviewed and exported.
8. **Legal hold workflow documented:** Confirm the team can select the user's container in the custodian data source picker where available or manually target the container for hold.
9. **IB exception handling documented:** Verify high-segmentation populations are either excluded from Pages/Notebooks or have compensating controls documented.
10. **Offboarding procedure updated:** Confirm user departure procedures address preservation of Pages/Notebooks content before cleanup windows expire.
